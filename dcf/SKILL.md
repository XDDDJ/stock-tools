# DCF 估值模型生成器

全自动三情景 DCF 估值，输入股票代码即可输出专业 Excel。

## 触发条件

- 用户要求「估值」「DCF」「这股票值多少钱」「给XX估值」
- 用户提供股票代码或公司名称 + 估值相关意图

## 工作流（6步）

### Step 1: 股票识别与确认

用户输入股票代码（`09992.HK`/`600519`/`AAPL`）或公司名称（`泡泡玛特`/`茅台`）。

**操作**：
1. 调用 `neodata-financial-search` skill 搜索股票
2. 展示确认卡片：
   - 公司名称 + 代码
   - 当前股价 + 市值
   - 所属行业
   - 最新财报年度
3. 用户确认后进入 Step 2

### Step 2: 自动拉取财报数据

调用 `finance-data-retrieval` skill 拉取以下数据：

| 数据项 | 优先 API | 备注 |
|--------|---------|------|
| 营业收入 | `income` | 最新年报 |
| 营业利润 | `income` | |
| 净利润 | `income` | |
| 经营现金流 | `cashflow` | |
| 资本支出 | `cashflow` | |
| 毛利率/净利率 | `income` 计算 | |
| 有息负债/净现金 | `balancesheet` | |
| ROE | `income` 计算 | |
| 总股本 | neodata | |
| 当前股价 | neodata | 实时 |
| 汇率（如需） | neodata | HKD/RMB、USD/RMB |

**市场识别规则**：
- `.HK` 后缀 → 港股，报告货币 CNY，股价 HKD，需汇率转换
- `.SH`/`.SZ` 后缀 → A 股，纯 CNY，无需转换
- 纯字母代码 → 美股，纯 USD

**容错**：
- 某项数据缺失时，用其他 API 交叉计算
- 全部缺失时提示用户手动提供

### Step 3: 行业假设推断

根据股票所属行业，从 `references/assumption_guide.md` 加载默认参数：

- 用最近 3 年历史数据校准（历史增速、FCF Margin 趋势）
- 自动生成三情景假设（乐观/基准/悲观）
- 展示推断结果给用户

### Step 4: 假设确认（对话式）

展示三情景假设表格，用户确认或微调：

```
┌──────────┬──────────────┬──────────────┬──────────────┐
│          │   乐观情景   │   基准情景   │   悲观情景   │
├──────────┼──────────────┼──────────────┼──────────────┤
│ Y1 增速  │    XX%       │    XX%       │    XX%       │
│ Y2 增速  │    XX%       │    XX%       │    XX%       │
│ ...      │    ...       │    ...       │    ...       │
│ WACC     │    XX%       │    XX%       │    XX%       │
└──────────┴──────────────┴──────────────┴──────────────┘
如需修改直接告诉我，确认无误回复"生成"即可。
```

**交互原则**：
- 默认值合理时，用户直接说「生成」即可
- 用户想改参数，直接说「基准增速改为 XX%」
- 支持整体调整：「乐观情景更激进一点」

### Step 5: 生成 Excel

1. 构建 config JSON（内存中或临时文件）
2. 运行 `python scripts/generate_dcf.py <config.json> <output.xlsx>`
3. 验证输出文件存在且大小合理

### Step 5.5: 生成后验证（必做！）

生成Excel后，**必须**用Python手动计算验证关键数值是否合理：

```python
# 快速验证：基准情景每股价值是否在合理范围
wacc = rf + beta * erp
# 计算5年FCF现值 + 终值现值 → EV → 股权价值(EV - 净债务)
# 每股价值 = 股权价值(十亿) * 10 / shares(亿) * fx_rate
# 与当前股价对比，检查涨跌空间是否合理（应在-50%~+100%之间）
```

**验证清单**：
- [ ] 每股价值数量级是否与股价相近（不应差10倍以上）
- [ ] 乐观情景每股价值 > 基准 > 悲观
- [ ] 概览页与情景页的每股价值、涨跌空间一致
- [ ] 敏感性矩阵中心值 ≈ 基准情景每股价值
- [ ] 投资评级与安全边际匹配

### Step 6: 交付 + 摘要

1. `deliver_attachments` 交付 Excel
2. 输出简要分析摘要（3-5句）：
   - 估值区间（悲观 ~ 乐观）
   - 当前价位的安全边际
   - 投资评级

## 投资评级标准

| 安全边际 | 评级 | 标签 |
|---------|------|------|
| > 40% | 强烈建议买入 | 🟢 |
| 20-40% | 建议买入 | 🟡 |
| -10%~20% | 观望 | ⚪ |
| < -10% | 建议卖出 | 🔴 |

## Config JSON 结构

### 单位规范（关键！）

| 字段 | 单位 | 示例（腾讯） | 说明 |
|------|------|-------------|------|
| `revenue` | **十亿** CNY/USD | 660.26 | 营收6602.57亿 → 写660.26 |
| `operating_profit` | **十亿** | 208.10 | 同上 |
| `net_profit` | **十亿** | 194.07 | 同上 |
| `operating_cf` | **十亿** | 258.52 | 同上 |
| `capex` | **十亿** | 62.93 | 同上 |
| `fcf` | **十亿** | 195.59 | 同上 |
| `net_debt` | **十亿** | -50 | 净现金写负数 |
| `shares` | **亿股** | 91.26 | 直接写亿股数 |
| `current_price` | 交易货币 | 479.2 | 港股写HKD，A股写CNY |
| `fx_rate` | CNY→交易货币 | 1.146 | 1 CNY = 1.146 HKD |
| 百分比字段 | 小数 | 0.529 | 52.9% 写 0.529 |

**注意**：金额数据统一使用"十亿"，股本使用"亿股"。这是代码中所有公式的计算基础。
**港股市值折算公式**：`每股价值(HKD) = 股权价值(十亿CNY) × 10 ÷ 总股本(亿股) × fx_rate`

## 踩坑记录

### 三重单位陷阱（2026-04-30）

代码中存在三重单位转换，任何一处出错都会导致结果偏差10倍：

1. **输入单位**：配置文件中的金额是"十亿"，股本是"亿股"
2. **中间计算**：EV是十亿CNY，需 ×10 转为亿CNY才能除以亿股
3. **输出转换**：CNY/股需 × fx_rate 转为 HKD/股

**公式链**：`B20 = D18(股权价值十亿CNY) × 10 ÷ B19(亿股) × fx_rate`

### 已修复Bug

| Bug | 现象 | 根因 | 修复 |
|-----|------|------|------|
| -99%下跌空间 | 三情景每股价值≈6 HKD | 配置中财务数据用了"亿"而非"十亿" | 统一为十亿 |
| 每股价值低10倍 | 乐观63 HKD而非724 HKD | B20公式缺 ×10 和 ×fx_rate | `=D18*10/B19*fx` |
| 概览页≠情景页 | 涨跌空间不一致 | 概览页重复算EV-净债务但路径不同 | 改为直接引用情景页B20 |
| 净债务调整缺失 | 情景页B20用纯EV | 未做净债务调整 | 增加D18=EV-净债务 |
| 敏感性分析缺×10 | 矩阵值低10倍 | Python计算中 equity/shares 缺×10 | 加上 equity×10/shares |
